Opcodes are used to instruct the VM to perform a certain action.

== Symbols

Throughout the documentation, there are certain symbols used to determine what kind of operand/data is needed in a specific place. Here are the symbols you will encounter and their meanings:

. The symbol R\{n} (e.g. Rx, Ry, R1, R2, ...) indicates a register.
. The symbol $\{n} (e.g. $x, $y, $1, $2, ...) indicates an operand that can be either a register, a constant or an immediate value.
. The symbol F\{n} (e.g. Fx, Fy, F1, F2, ...) indicates a function.
. The symbol T\{n} (e.g. Tx, Ty, T1, T2, ...) indicates a type.
. The symbol :\{n} (e.g. :x, :y, :1, :2, ...) indicates a label.
. The symbol <\{n}> (e.g. <x>, <y>, <1>, <2>, ...) indicates a scaled offset. A scaled offset is an integral value that its meaning depends on the memory region it is being applied on. A scaled offset of _N_ in a memory region of elements with _W_ bits width, refers to an offset of _N*W_ bits. For instance, an offset of 2 in an 8-bit memory region means 16 bits, or an offset of 10 in a 64-bit memory region means 640 bits. An offset itself can be retrieved from a register, a constant or an immediate value. But it must be an integer.

== Arithmetic

Arithmetic opcodes are used for performing various mathematical operations on data in the VM. There are two types of numbers in this VM, being Integer and Float. An Integer itself is of two kinds, being signed and unsigned.

=== Integer Arithmetic

IMPORTANT: The arithmetic opcodes related to integers are polymorphic. Meaning that the VM decides the appropriate operation to perform on the passed operands based on them being a signed or an unsigned integer. The operation being signed or unsigned is decided by the type of the first operand passed to it.

.Basic Integer Arithmetic Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Integer Addition | IADD | 0x25 | Rx $1 $2 | Rx = $1 + $2 | Adds two integers and stores the result in a register.
| Integer Subtraction | ISUB | 0x26 | Rx $1 $2 | Rx = $1 - $2 | Subtracts two integers and stores the result in a register.
| Integer Multiplication | IMUL | 0x27 | Rx $1 $2 | Rx = $1 * $2 | Multiplies two integers and stores the result in a register.
| Integer Division | IDIV | 0x28 | Rx $1 $2 | Rx = $1 / $2 | Divides (signed) two integers and stores the result in a register.
| Unsigned Integer Division | IDIVU | 0x29 | Rx $1 $2 | Rx = $1 / $2 | Divides (unsigned) two integers and stores the result in a register.
| Integer Modulus | IMOD | 0x2A | Rx $1 $2 | Rx = $1 % $2 | Stores the (signed) modulus of two integers in a register.
| Unsigned Integer Modulus | IMODU | 0x2B | Rx $1 $2 | Rx = $1 % $2 | Stores the (unsigned) modulus of two integers in a register.
| Integer Negation | INEG | 0x2C | Rx $1 | Rx = -$1 | Stores the negated value of an integer in a register.
|===

== Bitwise

Bitwise opcodes are to perform actions on the bits of the operands regardless of their data type.

CAUTION: Using bitwise operators on data might alter their payload's meaning whilst their header stays the same as before the alteration. Thus, inconsistencies might happen and terminate the program. Make sure that the altered data is still valid or cast it to an appropriate type.


.Bitwise Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Bitwise AND | AND | 0x41 | Rx $1 $2 | Rx = $1 & $2 | Stores the bitwise AND result of two operands in a register.
| Bitwise OR | OR | 0x42 | Rx $1 $2 | Rx = $1 \| $2 | Stores the bitwise OR result of two operands in a register.
| Bitwise XOR (exclusive OR) | XOR | 0x43 | Rx $1 $2 | Rx = $1 ^ $2 | Stores the bitwise XOR result of two operands in a register.
| Bitwise NOT | NOT | 0x44 | Rx $1 | Rx = ~$1 | Stores the bitwise NOT result of an operand in a register.
| Logical Left Shift | LLS | 0x45 | Rx $1 $2 | Rx = $1 << $2 | Logically shifts $1 by $2 bits to the left and stores the result in a register.
| Logical Right Shift | LRS | 0x46 | Rx $1 $2 | Rx = $1 >> $2 | Logically (unsigned) shifts $1 by $2 bits to the right and stores the result in a register.
| Arithmetic Right Shift | ARS | 0x47 | Rx $1 $2 | Rx = $1 >>> $2 | Arithmetically (signed) shifts $1 by $2 bits to the right and stores the result in a register.
| Left Rotation | LRO | 0x48 | Rx $1 $2 | | Rotate $1 to left by $2 bits and store the result in a register.
| Right Rotation | RRO | 0x49 | Rx $1 $2 | | Rotate $1 to right by $2 bits and store the result in a register.
| Population Count | CNTPOP | 0x4A | Rx $1 | | Count population (the number of bits equal to 1) in $1 and store the result in a register.
| Leading Zeros Count | CLZ | 0x4B | Rx $1 | | Count leading zeroes in $1 and store the result in a register.
| Trailing Zeros Count | CTZ | 0x4C | Rx $1 | | Count trailing zeroes in $1 and store the result in a register.
|===

== Logical (Comparison)

Logical opcodes are to compare operands and they all result in a boolean value.

=== Typeless

Typeless logical opcodes are unaware of the data type of the operand(s) passed to them. Their purpose is to check the equality/inequality of the data by comparing them bit by bit.

.Typeless Logical Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Bit Equality | BEQ | 0x4D | Rx $1 $2 | | Stores the boolean value resulted from the equality test on all the bits of two operands in a register.
| Bit Inequality | BNE | 0x4E | Rx $1 $2 | | Stores the boolean value resulted from the inequality test on all the bits of two operands in a register.
| Payload Equality  | PEQ | 0x4F | Rx $1 $2 | | Stores the boolean value resulted from the equality test on the payload bits of two operands in a register.
| Payload Inequality | PNE | 0x50 | Rx $1 $2 | | Stores the boolean value resulted from the inequality test on the payload bits of two operands in a register.
| Tag Equality | TEQ | 0x51 | Rx $1 $2 | | Sets Rx to true (1) if the types of $1 and $2 match.
| Tag Inequality | TNE | 0x52 | Rx $1 $2 | | Sets Rx to true (1) if the types of $1 and $2 don't match.
|===

=== Integer

Integer logical opcodes compare integers based on their values.

IMPORTANT: Integer comparison opcodes are polymorphic. The state of the opcode being signed or unsigned is decided by the type of the first operand passed to it.

.Integer Logical Opcodes

| Integer Inequality | INE | 0x54 | Rx $1 $2 | Rx = $1 != $2 | Stores the boolean value resulted from the inequality test of two integers operands in a register.
| Integer Less-than | ILT | 0x55 | Rx $1 $2 | Rx = $1 < $2 | Stores the boolean value resulted from the less-than test of two integer operands.
| Integer Less-than-or-equal | ILE | 0x56 | Rx $1 $2 | Rx = $1 \<= $2 | Stores the boolean value resulted from the less-than-or-equal test of two integer operands.
|===

== Data Operation

Data operation opcodes are used for moving (copying), storing or loading data. Such as to/from registers or to/from memory.

=== General

.General Data Operation Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Copy | COP | 0x00 | Rx $1 | Rx = $1 | Copy the value of $1 into the Rx register.
| Conditional Copy | COPIF | 0x01 | Rx $COND $1 $2 | Rx = $COND ? $1 : $2 | Conditionally sets Rx equal to $1 if $COND is true (1) or $2 if otherwise.
| Swap | SWAP | 0x02 | Rx Ry | temp = Rx; Rx = Ry; Ry = temp; | Swaps the values of the Rx and the Ry registers.
|===

=== Scaled Memory

Scaled memory data operations are to be performed on the regions of the memory which are classified per size. Further information can be found at the memory documentation.

NOTE: The symbol <\{n}> (e.g. <x>, <y>, <1>, <2>, ...) indicates a scaled offset. A scaled offset is an integral value that its meaning depends on the memory region it is being applied on. A scaled offset of _N_ in a memory region of elements with _W_ bits width, refers to an offset of _N*W_ bits. For instance, an offset of 2 in an 8-bit memory region means 16 bits, or an offset of 10 in a 64-bit memory region means 640 bits. An offset itself can be retrieved from a register, a constant or an immediate value. But it must be an integer.

.Scaled Memory Data Operation Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Load | LOAD | 0x03 | Rx $POINTER | Rx = memory[$POINTER] | Copy the value from the memory at the address of $POINTER into the Rx register.
| Load (with offset) | LOADO | 0x04 | Rx $POINTER <x> | Rx = memory[$POINTER + <x>] | Copy the value from the memory at the address of $POINTER plus the <x> offset into the Rx register.
| Store | STR | 0x05 | $POINTER $1 | memory[$POINTER] = $1 | Copy the value of $1 into the memory at the address of $POINTER.
| Store (with offset) | STRO | 0x06 | $POINTER $1 <x> | memory[$POINTER + <x>] = $1 | Copy the value of $1 into the memory at the address of $POINTER by an offset of <x>.
|===

=== Unscaled Memory

Unscaled memory data operations are to be performed on the regions of the memory which are classified as arbitrary sized (raw memory). Further information can be found at the memory documentation.

.Unscaled Memory Data Operation Opcodes
|===
| Name | Opcode | HEX | Operands | Semantic | Description

| Byte Load | BLOAD | 0x07 | Rx $POINTER $1 | Rx = memory[$POINTER] | Copy $1 bytes of data from the memory at the address of $POINTER into the Rx register (used for raw-memory operations).
| Byte Load (with offset) | BLOADO | 0x08 | Rx $POINTER $1 $OFFSET | Rx = memory[$POINTER + $OFFSET] | Copy $1 bytes of data from the memory at the address of $POINTER by an offset of $OFFSET bytes into the Rx register.
| Byte Store | BSTR | 0x09 | $POINTER $1 $BYTES | | Copy $BYTES bytes of data from $1 into the memory at the address of $POINTER.
| Byte Store (with offset) | BSTRO | 0x0A | $POINTER $1 $BYTES $POINTER_OFFSET $DATA_OFFSET | | Copy $BYTES bytes of data starting from an offset of $DATA_OFFSET bytes from $1 into the memory at the address of $POINTER by an offset bytes.
|===

=== Logical (Comparison)

NOTE: All the comparisons made on vectors return a mask. A mask is always a vector of the same size with the same count of lanes as the original vector, but the lanes are of the unsigned int type correspondent of the lane size of the original vector. A mask's lane is filled in zeros if the comparison resulted in a falsely value, and in ones if it resulted in a truely value.
